# 句子生成器基础设施修复与复查报告

日期：2026-07-30  
执行方：GPT-5 Codex

## 一、结论

本轮修复已经完成，当前原型在它明确支持的范围内通过全部自动校验。

这里的“通过”只表示：SV、SVP、SVO、There be 四种基础句型，以及原型当前开放的时态、肯否和一般疑问组合，可以按现有规则生成或安全拒绝。它不表示整个 `sentence.html` 已经实现，也不表示所有英文句法都已经覆盖。

系统没有读取用户个人的 `words.json`。所有验证只依赖系统 `patch/*.json` 与 `patch/sentence/` 下的规则补丁。

## 二、本轮修复的问题

### 1. 精确选项不得被静默改写

调用方通过 `choice` 指定名词数量时，现在把它当作精确请求：

- `water + plural` 返回 `there_be_number_unmet`。
- `scissors + singular` 返回 `there_be_number_unmet`。
- 生成器不会擅自把用户指定的复数改成单数，或把单数改成复数。

### 2. 禁止句改为逐句真实统计

原先的统计可能出现“一组里只执行一条，却看起来整组都执行过”的误导。现在每条禁止句使用 `(test_id, sentence)` 单独登记：

- `exec_forbidden` 必须用 `forbidden_sentence` 指向本组的一条禁止句。
- 可以由生成器验证的错误组合，必须命中指定拒绝码。
- 可以由独立检查器验证的错误句，使用 `check_info` 提供结构化上下文，并必须命中 `reason`。
- 尚无实现路径的禁止句继续保留并明确列为未执行，不再伪装成通过。

### 3. 补强独立语法检查器

检查器现可识别以下错误：

- 缺少 be：`You happy.`
- be 与主语不一致：`Am you happy?`
- do/does/did 与主语或时态不一致。
- do-support 后没有使用动词原形：`Did she ate an apple?`
- 一般过去式错误：`She eated an apple.`
- 完成时 has/have 不一致，或误用过去式：`She has ate an apple.`
- 不可数名词错误使用 `a/an` 或数字：`a water`、`two waters`。
- a/an 发音特例：`A hour`、`an university`。
- 错误表语和不可分级形容词：`tastes well`、`very dead`、`more alive`。
- There be 的数一致与特指限制。
- 已登记动词的宾语搭配限制。

同时修复了检查器对大写代词 `I` 的误判；`Do I paint?`、`Did I arrive?` 不再被当作错误句。

### 4. 搭配数据不再假装完整

过去用通用标签 `object` 标记大量动词，但这个标签几乎等于“什么名词都能当宾语”，会放行 `play a pencil` 一类不自然搭配。

现在数据分为两类：

- `verb_restrictions`：11 个具有具体、可运行规则的动词。
- `unresolved_verbs`：77 个确认拥有 SVO 框架、但尚未补齐可靠宾语规则的动词。

`object` 已从搭配 Schema 和名词搭配标签中删除。待补动词不会进入随机 SVO 生成池，也不会因为数据看似存在而被误认为已经支持。

这不是按“初学、中级、高级”分别维护多套安全词库。搭配和语义补丁是一套全局语言知识，各学习阶段只决定开放哪些公式和复杂度，不重复标注同一个单词。

## 三、数据契约变化

- `collocations.json` 新增必填数组 `unresolved_verbs`。
- `verb_restrictions` 与 `unresolved_verbs` 不得重叠。
- `unresolved_verbs` 中的动词必须存在于 `verb_frames.json`，并且必须声明 SVO 框架。
- 搭配标签不再允许无筛选能力的 `object`。
- 黄金禁止用例的 `exec_forbidden` 必须包含 `forbidden_sentence`。
- 禁止句可选 `check_info`；一旦存在，黄金测试就必须实际调用检查器并命中 `reason`。

## 五、仍然存在的边界

1. 28 条未执行禁止句对应尚未实现的能力，包括被动、SVOO、SVOC、固定介词、祈使句、名词主语一致、plural-only 名词短语、集体名词、副词位置和比较级等。这些不是本轮遗漏，而是第一版尚未开放的范围。
2. 77 个 `unresolved_verbs` 目前会被保守排除。它们需要逐个补充有证据的具体搭配规则，不能批量填回 `object`。
3. 组合矩阵仍报告 32 条“语法正确但意思不自然”的提示，例如抽象名词配具体地点。当前策略是提示而不阻断；后续应补全局语义关系，不应按学习阶段复制多套词库。
4. `mini_generator.py` 是 Python 原理验证工具，不是 Flutter 生产实现。将规则迁移到 Dart 时，需要复用相同数据契约和回归用例。

## 六、请 Hy3 重点复查

1. 检查 `choice` 的精确请求语义是否在所有生成路径一致，尤其是数量、动词、主语、宾语和地点。
2. 检查 53 条禁止句的逐句统计是否真实；不得用测试组数量代替句子数量。
3. 随机抽查 `check_info` 是否仅提供上下文，没有把期望答案直接喂给检查器。
4. 检查 `verb_restrictions` 的 11 条规则是否都有实际筛选能力，且 `unresolved_verbs` 的 77 个动词均具备 SVO 框架。
5. 确认任何代码和数据中都不再把通用 `object` 当作有效搭配规则。
6. 复跑本报告列出的全部测试，并核对数字，不只检查退出码。
7. 特别回归 `Do I paint?` 与 `Did I arrive?`，确认大写 `I` 不会再次导致检查器误报。
8. 对 28 条未执行禁止句逐条核对延期原因；只有对应生成能力落地时才补执行，不能为了提高数字而写假测试。

## 七、复查时应保持的判断标准

- 语法不合法：必须拒绝。
- 用户精确指定的选项不兼容：必须返回稳定拒绝码，不得静默换词或改数量。
- 语法合法但语义奇怪：当前记录为语义提示；有可靠规则后再升级为过滤条件。
- 没有可靠数据：进入 unresolved 并安全失败，不能用宽泛标签假装支持。
- 尚未实现的句法：明确 SKIP 和延期原因，不能宣称已经覆盖。

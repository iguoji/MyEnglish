# MyEnglish

MyEnglish 是一款面向个人长期使用的 Android 英语单词学习应用。词库、分组、复习记录和学习进度主要保存在手机本地，不需要注册账号。

当前版本：`v1.5.0`（构建号 `40`）

> 当前只提供 Android 版本，暂不支持 iPhone 和 iPad。

## 下载与安装

前往 [GitHub Releases](https://github.com/iguoji/MyEnglish/releases) 下载最新 APK，在 Android 手机上打开并安装。

如果系统阻止安装，需要在手机设置中允许当前浏览器或文件管理器“安装未知应用”。这是 Android 对非应用商店 APK 的常规保护设置。

## 第一次使用

应用不会附带或自动导入任何默认词库。首次打开时词库为空，你可以：

- 打开右上角菜单，点击“添加单词”逐个录入。
- 点击“数据导入”，选择自己的 JSON 词库或之前由 MyEnglish 导出的备份。

导入会替换当前词库。已有数据时，建议先使用“数据导出”保存一份备份。

## 首页

首页集中显示当前学习状态：

- 复习趋势：查看最近 7 天或 30 天每天复习的单词数量。
- 复习质量：按日期显示复习情况，点击具体日期可在旁边查看当天复习数量。
- 今日复习：四种复习模式分别显示今日状态——待完成（红）、进行中（蓝）、已完成（绿）。每张卡片底部有一条双层进度条：底色表示今日主线完成与否（灰=未完成，绿=已完成），前景表示当前这一局的进度（绿=主线局，蓝=巩固局），按当前会话已完成的单词数比例填充。主线未开始时全灰；主线进行中绿在灰上；主线完成后全绿；巩固开始后蓝覆盖在绿上，巩固完成则全蓝。主线的判定标准是「把今天这批单词操作完一遍就算过」，答错不影响过关与否，只会累计进结算页的错误次数展示。
- 词库入口：复习模式下方用分隔线夹着「向上滑动展开词库」文字提示，在首页进行较长距离的上滑手势即可打开完整词库。

从任意复习模块返回首页时，顶部「今日复习 X/目标」、四张模式卡的状态、复习趋势曲线和复习质量日历会一起重新统计，不需要重启应用就能看到刚才的成绩。

词库展开后，可以点击顶部手柄或使用 Android 返回手势将其收起。

## 词库管理

词库支持以下操作：

- 搜索单词，点击单词播放发音并展开释义。
- 新增、编辑和删除单词，维护音标、词性、释义、难度及常见词形变化。
- 创建、重命名、排序和删除自定义分组。
- 按分组、难度、复习时间、更新时间或加入时间查看词库。
- 按字母、含义复杂度、难度或日期排序。
- 批量选择单词，并移动或复制到其他分组。

“含义”排序会先比较释义数量；数量相同时，再比较全部释义文字的字符总数。

## 随身听与听音辨义

词库底部提供两个普通学习入口。没有勾选单词时使用当前可见列表；勾选后只使用已选单词。

### 随身听

- 自动播放固定列表中的单词。
- 支持上一词、下一词、暂停和继续。
- 支持搜索跳转、显示或隐藏答案。
- 支持设置重复次数、播放间隔和列表循环。
- 支持锁屏、通知栏和蓝牙耳机媒体控制。
- 退出后保存进度，可从词库底部继续。

### 听音辨义

- 先根据发音选择正确的英文单词。
- 再依次选择对应的中文释义。
- 记录错误次数、提示次数和答题结果。
- 错误会提高单词难度；连续正确达到规则要求后会降低难度。
- 候选项和未完成进度会保存在本地，可在当天之外继续普通听音辨义。

## 今日复习

首页提供四种复习模式：

| 模式 | 当前状态 | 说明 |
|---|---|---|
| 听音辨义 | 可用 | 首页复习入口与词库底部普通听音辨义共用同一套流程，完成量单独计入该模式 |
| 词义连连 | 可用 | 限时把英文和中文释义两两连线，界面复刻 `ui/词义连连.html` 原型 |
| 拼写巩固 | 可用 | 听发音、看释义，用片段或逐字母两种方式拼出单词，界面复刻 `ui/拼写巩固.html` 原型 |
| 看义选词 | 暂未开放 | 当前进入独立占位页 |

四种模式每天共用同一批单词，但各自保存独立进度。每日数量取自右上角菜单中的"每日复习"设置，默认 50 个。

### 拼写巩固

听单词发音、看中文释义，把单词拼出来。占位格下方会列出该单词的
全部含义和词性（逐条对齐），拼写时可直接比对。拼法由音节切分算法决定，分两种：

- 片段模式：能拆开的词（如 tradition → tra / di / tion）把正确片段和一批形近干扰项打乱，按顺序挑对。
- 逐字母模式：拆不开的短词（如 bowl）或含空格、连字符的词（ice cream、T-shirt）用 26 键键盘逐字母拼。

底部两个工具：刷新换一种拆分方式、剪刀自己动手拆分。一个词错满两次会自动揭示答案并计入「需加强」，既避免卡死，也让答错有真实代价。

### 主线与巩固

每个模块每天有两种局：

| 类型 | 什么时候开 | 单词来源 | 是否推进复习时间 |
|---|---|---|---|
| 每日主线 | 今天还没过关时 | 今天这份词库的全部单词 | 是 |
| 无限巩固 | 今天主线已经过关后 | 今天随机一半 + 明天随机一半 | **否** |

巩固局不推进复习时间是刻意的：那批词里混着明天要背的，一旦推进，按「复习时间升序」排序时它们会掉到最后，明天就选不到了。这样一批单词才能在几个模块里反复练，而不会被提前消耗掉。

### 一局的结果

| 结果 | 条件 |
|---|---|
| 完成 | 整局跑完，而且一次错都没有 |
| 失败 | 整局跑完但中途错过，或者倒计时耗尽 |
| 中断 | 改了「每日复习」数量，或者局里的单词被删掉了 |

答错不会当场结束这一局——剩下的题照样做完，结算时再按总错误数判定。只有拿到一次「完成」，模块卡片才会翻绿；否则再进去就是从头再来一遍。跨天时昨天还挂着的局会被自动收成「中断」。

### 词义连连玩法

- 每 5 个单词分成一组：左列是英文，右列是被打乱顺序的中文释义。
- 点一张左卡再点一张右卡，配对正确会画出一条绿色曲线并划掉这一对；配对错误则两张卡红框抖动。选中左卡时会播放该单词的发音，让用户边听读音边找对应释义。
- 一组 5 对全部连完后自动切换到下一组，直到当天词单全部连完。

候选词卡片有四种状态，按 `ui/词义连连_部分效果.html` 复刻：

| 状态 | 表现 |
|---|---|
| 默认 | 白底、极淡描边，左列英文加粗、右列释义偏灰 |
| 选中 | 蓝色描边加淡蓝底、文字转蓝，整卡轻微放大并向下打出一束蓝色柔光，内侧圆点放大发亮 |
| 连对 | 淡绿描边加极淡绿底、绿色文字划掉，整卡略微缩小并淡到 45%，随后不再响应点击 |
| 连错 | 淡红描边加极淡红底、红色文字，卡片左右甩动并带一点歪头；这 0.4 秒内不接受新的点击，保证看得清错在哪 |

- 顶部中间显示“已配对 / 总对数”，与听音辨义的题号样式一致。
- 顶部横条表示**剩余时间**占比，最后 10 秒会转成红色并让倒计时数字呼吸闪动。
- 每局时长默认 150 秒，可在右上角菜单的“词义连连”一项里以 30 秒为步长调整。
- 点一下右上角倒计时可 +30 秒。这个操作同时会把菜单里的“词义连连”默认秒数一起 +30，下次进入就从更长的时间开始。
- 时间耗尽或全部连完后进入结算页，展示最高连对、配对失误、剩余时间和完成词汇，并可以“再挑战一次”。
- “再挑战一次”会退回首页并立刻重开一局。这样「下一局该开主线还是巩固」始终由同一套规则决定，用户感受上仍然是点一下就重开。
- 中途退出会冻结进度，当天再次进入可以接着玩；累计连错数也会接着数，不会因为退出重进而归零。
- 每连对一张左卡就写一条复习记录。连错算在**左卡**头上——左卡是你正在安置的那个单词；这张卡最终连对时，累计的连错次数一起交给数据库，用来更新连对次数和难度。没连上的卡不写记录。

今日词单按以下顺序挑选：

```text
复习时间升序（没复习过的排最前）
→ 释义数量少的优先
→ 释义字符少的优先
→ 难度高的优先
→ 字母升序
→ 编号升序
```

需要知道的一点：复习时间精确到毫秒，两个词几乎不可能撞上同一毫秒，所以只要一个词复习过，第一条基本就能分出胜负。也就是说后面几条主要在「还没复习过的那批词之间」起作用。

## 发音与离线语音

可以在右上角菜单切换美式或英式发音。播放顺序如下：

```text
本地 MP3 缓存
→ 不背单词网络音频
→ 有道网络音频
→ Android 系统离线英语 TTS
```

TTS 是手机系统提供的文字转语音功能。应用只选择系统标记为可离线使用的英语声音；如果手机没有离线英语语音包，需要先在系统设置中安装。

菜单中的“离线语音”会尝试把当前词库全部单词的“不背单词 / 有道”两个网络渠道、
美式和英式两种口音都下载到本地，并显示缓存进度。进度以单词为单位：一个单词只要
有一家渠道同时缓存了美式和英式，就算已缓存。网络音频连续失败后，应用会在 5 分钟内
优先使用系统 TTS，减少重复等待。

### 复习模块的轮转渠道朗读

在听音辨义、词义连连、拼写巩固三个复习模块里，播放或点按重听当前单词时，
会在当前口音下按固定顺序轮转一个发音渠道来读，而不是每次都走固定顺序：

```text
不背单词网络音频 → 有道网络音频 → 系统离线英语 TTS → 不背单词……
```

第一次播放从“不背单词”开始，下一次用“有道”，再下一次用系统 TTS，之后回到
“不背单词”，以此类推。这样反复点击重听能稳定听到多个来源的声音，又不会因为真
随机而出现同一家连续读多次的情况。每个网络渠道会在本地独立缓存，离线时优先复用
已有缓存；用户设置的美式/英式口音不会被轮转渠道打断。

## 数据导入、导出与清空

- 数据导入：支持单词数组，或由 MyEnglish 导出的完整备份对象（含词库、分组、设置、会话与复习记录）。
- 数据导出：保存全部本地数据，包括单词、释义、分组、设置、每日词库、复习会话与记录、学习会话、听音候选项缓存和音节划分，文件名类似 `MyEnglish-2026-08-19.json`。
- 清空数据：经过二次确认后，清空词库、分组、全部会话与复习记录、候选/音节缓存、设置和离线 MP3，恢复到首次安装状态。

导出的完整备份是应用数据的完整镜像：换机或重装后“数据导入”即可还原除离线语音 MP3 以外的全部学习进度与统计。

## 数据与隐私

- 单词、释义、分组、设置和学习记录保存在 Android 应用私有目录。
- 应用不提供账号系统，也不会把整份词库上传到项目服务器。
- 播放或缓存网络发音时，会把当前单词拼写发送给对应的公开音频服务。
- Android 卸载应用后，系统会删除应用私有目录中的本地数据。

## 本地数据结构

业务数据保存在 `my_english.db`，位于 Android 应用私有数据库目录。主要表：

| 表 | 用途 |
|---|---|
| `words` | 单词主体、难度、音标、词形和时间字段 |
| `meanings` | 词性与释义数组 |
| `groups` | 自定义分组 |
| `group_positions` | 分组在界面中的顺序 |
| `group_members` | 单词与分组的多对多关系 |
| `listening_meaning_option_cache` | 每道听音辨义题的候选项和正确答案位置 |
| `learning_sessions` | 随身听和词库底部普通听音辨义的长期进度 |
| `daily_word_sets` | 当天四个复习模块共用的单词主键顺序 |
| `review_sessions` | 每个模块每一局的类型、状态、单词快照与页面进度 |
| `review_records` | 每次答题的连对次数、模块、所属会话、错误、提示、前后难度与前后复习时间 |

复习侧的三张表构成完整链路：**每日词库 → 模块会话 → 复习记录**。

- `daily_word_sets` 一天只有一行，四个模块共用；
- `review_sessions` 自带 `word_ids_json` 快照，而不是只存词库编号——巩固局的单词横跨今明两天，不属于任何一份词库，光靠编号还原不出来；
- `review_records.streak` 直接存连对次数，写记录时只取上一条即可，不必再回头扫一整串历史。

数据库版本 12 丢弃了旧的 `daily_review_plans` 与 `record`，改建上面三张表。词库、释义、分组完全不受影响。

## 导入与导出格式

导入支持两种 JSON 顶层结构：

```json
[
  {
    "spelling": "example",
    "meanings": [
      {
        "index": 0,
        "pos": "n.",
        "definitions": ["例子"]
      }
    ]
  }
]
```

或者使用完整备份结构：

```json
{
  "words": [],
  "groups": [],
  "members": []
}
```

Android 导入层通过 SQLite `PRAGMA table_info` 读取真实字段作为白名单：存在的字段按数据库类型写入，未知字段忽略。导入是整库替换，不是追加；完整备份会还原词库、分组、设置、每日词库、复习会话与记录、学习会话、听音候选项缓存与音节划分。

## 每日复习实现

`ReviewWordSelector` 只接收完整词库和目标数量，不依赖首页当前搜索、分组或排序按钮。固定比较链为：

```text
reviewedAt ASC（null 最前）
→ meaningCount ASC
→ meaningCharacterCount ASC
→ difficulty DESC
→ spelling ASC（忽略大小写）
→ id ASC
```

`ReviewFlow` 把入口动作收敛成两步：

**resolveWordSet —— 备好今天这批词**

目标数量取 `min(每日复习, 词库实际数量)`。只录了 30 个词却把目标设成 50 时，如果不取小值，每次打开模块都会白写一次词库，而且主线永远判不了完成。

已有词库时先剔除被删掉的主键，再比对数量：多了从前面截取，少了就**排除已有 id** 再从排序结果补足。排除这一步不能省——已经练过的词复习时间刚被推进、掉到了排序后面，没练的仍排在最前，不排除的话补进来的就是词库里已有的那几个，同一个词会出现两次。

**openModule —— 决定这一局怎么开**

```text
今天最新一条会话还在「进行中」且单词仍然有效 → 直接续上
今天已有一局「完成」的主线                    → 开巩固局（今天一半 + 明天一半）
其余（没开过 / 中断 / 失败）                  → 开主线局（整份词库）
```

「明天的词」用**排除今天这批**之后排最前的那些，而不是「跳过前 N 个」：今天的词已经掉到排序末尾，跳过前 N 个会跳错位置；词库总量不足两倍目标时更会直接把今天的词又抓回来。明天的词不够一半时，缺口由今天补足，题量不缩水。

**统计口径**（顶部「今日复习 X/目标」、趋势曲线、打卡热力图三处完全一致）：只统计 `is_correct = 1` 的记录，也就是「这一遍一个都没错」。练了但错过的词不算数——用户要看的是今天真正拿下了多少个词。不区分模块，也不区分主线还是巩固：练了就算。

**难度与连对次数**（全部在原生一个事务里完成）：

- 本次出过错 → 连对次数归 0，难度 +1；
- 本次一气呵成 → 连对次数在上一条基础上 +1；每满 5 的倍数（5、10、15…）难度 -1，下限 0。

连对次数跨模块累计：听音辨义答对、词义连连接着答对，算连续两次。

## 音频实现

Flutter 通过 `my_english/word_audio` MethodChannel 调用 `WordAudioPlayer`。Android 侧负责：

- 读取和写入 App 私有目录中的 MP3 缓存（普通播放按口音合并存储，按渠道播放按渠道分目录存储；离线预缓存会尝试补齐所有网络渠道）。
- 依次尝试不背单词与有道网络音源。
- 检查网络状态，并为连续失败保存 5 分钟冷却时间。
- 使用 Android `TextToSpeech` 作为离线兜底。
- 通过 `MediaSessionCompat` 和 MediaStyle 通知提供系统媒体控制。

网络音频来源：

- 不背单词美式：`https://audio.beingfine.cn/speeches/US/US-speech/{spelling}.mp3`
- 不背单词英式：`https://audio.beingfine.cn/speeches/UK/UK-speech/{spelling}.mp3`
- 有道美式：`https://dict.youdao.com/dictvoice?audio={spelling}&type=2`
- 有道英式：`https://dict.youdao.com/dictvoice?audio={spelling}&type=1`

`key.properties` 和 keystore 都包含敏感信息，不得提交到 Git。Release APK 默认生成在：

my_english/build/app/outputs/flutter-apk/app-release.apk

- `ANDROID_KEYSTORE_PASSWORD`

- `ANDROID_KEY_PASSWORD`

## 当前限制

- 仅保留 Android 工程，尚未支持 iOS。
- 看义选词目前只有入口与占位页；它不建词库也不开会话，因此不会在首页显示「待完成」。
- 词义连连的结算页保留了顶部返回键与数字进度（原型是整屏结算），以免结算后没有可见的返回入口。
- TTS 的声音质量和离线能力由手机安装的语音引擎决定。
- 复习时间按毫秒时间戳排序，因此「难度高的优先」等后续条件在日常使用中几乎不会被触发（只对从未复习过的词生效）。想让难度真正参与日常排序，需要把第一层改成按复习**日期**比较。

## 代码约定

- 页面采用目录式组织，页面专属组件与服务放在对应页面目录。
- 所有界面图标统一使用 Tabler 图标。
- Dart 和 Kotlin 保留中文注释，解释关键数据流、参数和返回值。
- SQLite 的批量导入、清空、答题记录和难度更新使用事务保证一致性。
- 网络音频先写临时文件，校验 MP3 文件头后再替换正式缓存。

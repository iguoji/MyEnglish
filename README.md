# 我的英语（MyEnglish）

一款通过听音、配对、拼写和选词来加深单词记忆的个人英语学习应用。目前提供 Android 版本，词库和学习记录保存在手机本地，无需注册账号。

当前仓库版本：**2.4.0（构建号 59）**，以 [pubspec.yaml](my_english/pubspec.yaml) 为准。

本说明对应当前的新结构实现。备份格式的 `version: 3` 与应用版本号是两件事。

## 普通用户使用说明

### 首次使用与旧数据

新结构使用独立的本地数据库，首次打开时词库为空；原来的数据库文件保留，不会自动转换旧词库和旧练习记录。

- 通过右上角菜单添加单词，或者导入已经整理好的新版完整备份。
- 导入会替换当前新版数据库中的业务数据；格式或关联有错误时，整次导入撤回，保留导入前的数据。
- 旧版备份需要先转换成新版格式，不能直接导入。已有的 [转换脚本](my_english/tools/convert_backup_to_v3.py) 支持 version=2，搬运词库及适用设置，计划和练习历史留空。应用不会为了升级而卸载程序。
- 卸载应用仍会删除应用的本地数据，备份应保存在应用之外。

### 词库管理

在首页向上滑动展开词库，点击顶部手柄或系统返回操作收起。

- 点击单词播放发音，并展开或收起含义。
- 向左滑动单词行，可以编辑或删除。
- 搜索按英文拼写查找，忽略大小写并支持部分拼写。
- 单词按难度分区；分区内可选择默认、含义、难度或日期排序。
- 支持勾选、全选和反选。随身听未勾选时使用当前搜索结果，勾选后按当前分区和排序播放选中单词；自测必须明确勾选 5–100 个单词。勾选按单词编号识别，搜索、刷新和从模块返回后仍然保留。

普通删除只做删除标记。正在进行的练习保留开局时的内容副本，编辑或删除词库中的单词不会改变已经出的题；以后的计划和新练习使用新内容。

### 五种学习方式

| 方式 | 玩法 |
| --- | --- |
| 随身听 | 按列表播放，支持搜索、跳词、暂停、显示含义、重复和循环。默认每词两遍、间隔两秒、开启循环。 |
| 听音辨义 | 先听发音选择拼写，再逐条选择含义；完成一个词后可以再试一次或进入下一词。 |
| 词义连连 | 不限时连接英文和中文，每轮最多五对，同轮中文不重复；优先安排不同单词，必要时用其他单词的旧配对补位。 |
| 拼写巩固 | 听发音、看含义，用26个字母键拼词；空格、撇号和连字符自动显示，整词填完后判断。 |
| 看义选词 | 看中文选英文，每题固定四个候选，其中一个或两个正确；对应单词更多时拆成多题，穿插练习。 |

同一个词的相同中文含义可以合并练一次，同时保留原始词性记录。例如 `vi. 吃` 与 `vt. 吃` 的资料分别保存，练习时合并。

选择题的候选来自题目答案与混淆选项。英文按字母排序，中文按字符编码固定排序；混淆选项从对应单词或含义的混淆字段取得，缺少时生成并保存。已经出的题恢复后保持同一份候选内容。

词义连连会把多义词分散到各轮，先尝试不同单词、不同含义的组合；其他单词的旧配对也无法补齐时，才允许同轮出现同词的其他含义。最后一轮不强行补满。新安排只影响新建会话，继续旧会话仍按原题序进行。

选择题点击后立即显示对错反馈，答案保存成功后再推进；下一题候选提前准备。看义选词和拼写巩固答对后的固定停留缩短到约 0.35 秒，看义选词在下一题准备完成后一起替换题目和候选。听音辨义的阶段切换、看义选词换题与词义连连换轮加入短过渡，保留外层卡片的稳定位置。

听音辨义和看义选词共用候选样式：卡面与外框保持中性色，候选正文居左，序号作为右侧辅助标记；答对、答错后，右侧原位切换为 Tabler 对勾或叉号，红绿只用于图标，错项文字适当弱化，反馈保留短淡入。

换题或刷新候选后，等所有手指松开并停止连点约 0.35 秒，再接受新的答案，避免上一题的连点误记到下一题；题目淡出时保留已填字母的显示状态，避免填字动画重新开始造成闪现。

随身听的搜索不改变真实播放列表。暂停时保留当前词、已完成遍数和剩余间隔；未读完的这一遍从头朗读。切到后台或锁屏仍会暂停。随身听的播放设置通过页面上滑打开，正常列表滚动优先。

随身听独立于复习会话：设置中只保留一份按顺序排列的单词编号、当前位置、用时和播放状态，新开始覆盖清单，继续和重播更新原清单，不再新增会话或复制单词正文。每次播放前读取最新单词，已删除的词自动剔除并跳过；清单跨天保留。首次升级会接续最后一次旧随身听的顺序与位置，历史记录保留。

### 每日计划、巩固与自测

每日复习默认50个词。四个首页模块共用当天的一份计划，同时提前准备明天的计划。

- 选词分两层：难词占 40%，先按难度降序；久词占 60%，先按最久没复习。两层的口味是相反的——难词层接着按含义条数、含义字数降序（又难又重的优先），久词层接着按含义条数、含义字数升序，再按难度升序（又轻又久的优先）。两层最后都按字母序、编号升序。
- 每次获取计划都检查删除和数量变化，保留有效单词，缺少时补充；多余时按 40/60 的配额从两层里各减一部分，不会只砍掉排在后面的久词。
- 词库暂时只有30个词而设置为50时，先使用30个；设置仍保留50，后续词库增加后继续补足。
- 修改每日数量只调整计划，已经开始的练习继续完成原来的试卷。设置为0时不创建新复习局，已有会话仍可继续。
- 巩固先从今日、明日各取一半，缺额优先补剩余明日词，再补剩余今日词，尽量达到每日数量；同局不重复加入同一个单词。
- 例如每日50词、明日只有10词，巩固使用“今日25＋明日10＋今日再补15”，共50词；总共只有30个不同单词时不会复制单词硬凑50。

词库入口悬浮在底部中央，不占列表高度：第一行是无背景的单词数量，第二行是约 187×48 的单个胶囊，内部以两条细线分为切换、当前模块、继续三个区域。默认随身听；中间可用时为 Tabler 蓝底白字，左侧切换始终以蓝色提示可操作，右侧无有效进度时为灰色禁用。点击左侧可在五种模块间切换，菜单沿中轴向上展开，共用外轮廓，列表保持中性底色，仅当前项使用浅蓝色；点菜单外可收起。

新建自测统一要求选择 5–100 个单词，数量不足或超出时中间区域禁用，长按可查看原因；随身听不受此上限限制。列表末尾有额外滚动余量，最后几个词也能滚到悬浮入口上方。

从词库明确带着选词进入，会新建自测，即使与上次选的是同一批词。胶囊右侧的继续图标恢复当前模式的原进度，不要求重新勾选；“再来一次”沿用原自测词单。首页复习与自测分别保存进度。

首页四张卡展示每日复习／巩固，胶囊恢复独立自测，两者的状态分别计算。自测必须已有保存的作答记录才启用继续，刚打开就返回的空局不提供恢复；按钮查询和实际恢复使用同一判断，已有答案不会被清除。随身听仍按独立播放清单判断能否继续。

普通退出保留进度，跨天的未完成会话会被中断。把本局全部题目做完就算完成，过程中答错不导致整局失败；完成后的巩固不会撤销当天模块的已完成标记。

### 结算和首页统计

答题时保存每次答案，完成后在统一结算页查看单词结果和难度建议。用户可以逐词选择变难、变易或不变，离开结算页时才正式应用。

- 一局中同一个词的所有题目都完成，而且当前这一遍全部答对，该词才算本局正确。
- 听音辨义点击“再试一次”会让整个单词进入新一遍；结算只看最后一遍，旧答案仍保留。
- 看义选词误选时，这道题考察的所有正确单词都记错，不把错误归给干扰词。
- 本局答错建议难度加1；连续答对达到“连对变易”（默认5）后，每次再答对建议减1，最低为0。
- 复习结算更新最近复习时间；巩固、自测只调整难度。随身听不答题，也不产生结算。
- 应用意外关闭后会补交已完成但尚未落实的结算，同一局不会重复调整难度。

首页顶部“今日复习”、曲线和热力图共用同一规则：**只统计已经正式落实结算的单词，答错也算练过，同一天同一个词只计一次。** 复习、巩固、自测都参与；数量可以超过每日目标。

只练半局而尚未提交结算时，首页数字暂不增加。第二天补结算仍记回这局会话所属的日期。后续答错不会扣减当天已经练过的单词数量。

模块进度从会话读取；已收录词数从词库读取；最近表现和连续答对次数来自结算。页面停留时间与实际答题时间分别保存，后台时间不计入；听音辨义和拼写巩固继续展示逐词实际用时。

### 设置、发音与备份

全局设置保留主题、口音、含义分隔符、字号、每日复习和连对变易。默认浅色、美式发音、每日50词；字号继续兼顾系统设置。

发音沿用“不背单词 → 百度翻译 → 有道 → 手机本地语音”的可用来源轮换。离线语音可以提前下载；没有可用网络发音时尝试手机英语语音。播放和下载需要相应来源可用。

新版完整备份包含词库、设置、计划、题目、答案、结算和恢复现场的数据；不包含下载的音频和运行日志。导入后立即重新读取主题、口音及随身听清单等设置；重置全部设置会清空随身听清单，四种复习模块的会话保留，清空全部数据则会一起清理。

## 开发者说明

### 实现入口

界面仍使用 Flutter/Dart，Android 通过 Kotlin 和 SQLite 保存数据。所有模块复用 `ModuleScaffold` 和 `SessionProgress`；选择题复用 `ChoiceOptionGrid`，听音辨义与拼写巩固复用 `AudioPlaybackCapsule`。

| 入口 | 职责 |
| --- | --- |
| `WordsDatabase.kt` | 单词、设置、通用读写和新版完整备份。 |
| `StudySchema.kt` | 十一张表、约束和索引的唯一建表入口。 |
| `StudyRepository.kt` | 计划维护、试卷保存、答题判断、重试、结算和统计。 |
| `review_flow.dart` | 首页与自测入口、难词穿插、巩固取词。 |
| `self_test_policy.dart` | 四种自测共用的 5–100 词限制及提示。 |
| `listening_playback.dart` | 随身听唯一的编号清单、续播位置及删除项处理。 |
| `question_builder.dart` | 整份试卷及同义拆题，大词库在后台编题。 |
| `matching_round_builder.dart` | 分散多义词，优先生成单词和含义均不重复的连线轮次。 |
| `question_options.dart` | 混淆字段复用、首次生成与题目候选保存。 |
| `session_progress.dart` | 共用写入队列、当前遍次、答题用时和结算控制。 |

数据库文件为 `my_english_v3.db`，结构版本为1；`my_english_v2.db` 保留。备份格式版本为3，两者与应用版本各自独立。

### 开局与换题性能

词库自测复用首页已经加载的单词。较大的试卷编排、开局请求编码和会话回包解码放到后台处理；数据库批量读取大小题、明细及当前遍次答案，并复用写入语句。首页自测“继续”标记只读取会话基本信息，进入页面时才读取整局内容。

随身听开局只写一个设置值并复用首页已有单词，不经过试卷构建、会话保存或整局回读。播放状态按调用顺序保存，每份新清单有独立编号，防止旧页面迟到的保存覆盖新清单；秒级进度更新不触发全局主题重建。自测在界面和开局服务共同限制为 5–100 词。

2026-09-14 模拟器验证：1130 词旧清单的顺序、位置及用时迁移一致；新建、跳词和续播后，随身听会话总数保持 54，播放设置始终只有一份。四种自测均以 5 词进入，来回切换保留勾选，继续自测恢复对应模式。本轮未重新采集点击至可操作的完整耗时，下面的历史数据对应此前的会话式随身听。

答题进度只发送变化的题目用时，按差额累计总答题时间；单词完成时直接取得当前词的结算草稿，避免每换一个词就读取整局草稿。候选提前准备并共用正在进行的请求，减少重复生成和保存。

运行日志中的 `study_performance` 记录开局的词数、题数，以及校验、保存、读取的耗时；这三段不包含数据库最终提交、来回传递及页面显示，不能直接当作用户等待的总时间。

需要完整测量时，构建命令增加 `--dart-define=PROFILE_STUDY_OPEN=true`。新增的 `study_open` 和 `study_open_native` 日志使用同一个 `trace_id` 对应一次点击，记录选词、编题、请求编码、数据库排队与最终提交、回包解码、首题候选以及页面淡入。终点按引擎帧编号匹配到“控件已启用、淡入已结束”的画面绘制完成时间；绘制数据不可用时明确标记，不把后续回传日志的延迟算入总时间。计时默认关闭，不保存单词或答案正文。

2026-09-13 在 Android 37 模拟器调试版中，用户以 1130 个词各打开两次：随身听为 1.248～1.488 秒，听音辨义为 2.147～2.440 秒。听音辨义最后一轮中，副本与题目保存加最终提交约 622 毫秒，读回、回包编码及对象重建约 732 毫秒。两部分都需要优化；这些数据不代表真机正式版。完整分段及采集边界见 [测量报告](outputs/session_open_profile_2026-09-13.txt)，原始记录见 [测量数据](outputs/session_open_profile_2026-09-13.json)。

第一轮尝试复用本次写入结果、省去整局回读，最终按维护优先原则撤回了两处业务代码，保留计时工具和测量记录。排除准备遍次后，随身听总耗时中位数从 1.289 秒变为 1.181 秒，听音辨义从 2.443 秒变为 2.160 秒；但随身听“题目写入＋组装”从 124 毫秒增加到 234 毫秒，用户也未感到明确改善，因此没有把局部收益当作所有模块的稳定收益保留。

第一轮的过程、原始数据及取舍见 [第一轮记录](outputs/session_open_round1_report.txt)。后续在用户授权的自主阶段继续逐项比较，分别保留测量与提交记录。

第二轮统一精简会话返回格式：大题、小题和关联明细只传页面模型实际使用的字段，新建、继续和重试共用一个转换函数。数据库仍完整保存后读取，备份和结算规则保持一致。1130 词时，随身听返回数据减少 16.84%，听音辨义减少 30.57%。同一 profile 性能采集包内交替比较，听音辨义总耗时中位数从 2.735 秒降到 2.466 秒；随身听从 1.351 秒变为 1.387 秒，未确认总耗时改善。环境为锁屏下的模拟器，不能外推真机固定收益。方法与限制见 [第二轮记录](outputs/session_open_round2_report.txt)。

词库读取超过 8 秒时显示“仍在准备”，同一请求随后成功会自动显示词库；重新加载通过请求编号阻止旧结果覆盖新数据。一次 22.8 秒的慢请求已验证会自动恢复，不再要求额外点重试；这不代表底层慢启动原因已经消失。

需要排除开发调试开销时，可用 `flutter build apk --profile --dart-define=PROFILE_STUDY_OPEN=true --target-platform android-arm64` 构建性能采集包；profile、debug 和 release 使用同一签名，可覆盖安装保留数据。新增计时默认关闭，诊断观察窗口最长三分钟，不改变业务等待或退出规则。

### 十一张业务表

| 表名 | 内容 |
| --- | --- |
| `settings` | 偏好设置与会话副本、混淆更新、播放状态。 |
| `words` | 拼写、难度、混淆词、保留的音节及复习时间。 |
| `word_meanings` | 每行一条原始含义，保存可空主词性、子词性与排序。 |
| `plans` | 每个日期唯一的有效计划。 |
| `plan_words` | 计划成员及难词／久词身份，按记录编号排列。 |
| `sessions` | 模块、日期、类型、状态、结算状态、当前大题及用时。 |
| `session_main_questions` | 大题顺序、阶段、重试次数及当前小题。 |
| `session_sub_questions` | 实际出现的小题、题型、内容、答案、混淆选项及用时。 |
| `session_question_details` | 小题对应的原始单词和含义，可保留合并含义的全部编号。 |
| `session_question_answers` | 小题编号、尝试序号、文本答案数组与对错。 |
| `session_word_settlements` | 每局每词一行，保存归属日期、草稿／落实状态及难度变化。 |

公共字段为 `id`、`created_at`、`updated_at`、`deleted_at`。时间戳统一使用整数毫秒；业务日期使用 `YYYY-MM-DD`；耗时为秒。普通查询排除软删除，备份包含软删除行。

会话类型：1复习、2巩固、3自测；状态：0失败、1完成、2进行中、3中断；结算状态：0未结算、1已结算、2无需结算。

会话单词副本保存在 `settings` 的 `session.<编号>.snapshot`。随身听的新清单与进度使用唯一的 `listeningPlayback` JSON 设置，旧 `session.<编号>.playback` 仅用于迁移及历史备份。混淆字段的后续更新分别保存到 `session.<编号>.confusions.word.<单词编号>` 和 `session.<编号>.confusions.meaning.<含义编号>`，恢复时合入原副本，避免每题重写整份词库；完整备份会一并保存这些条目，无需新增表或字段。

偏好读取及重置排除上述会话条目。候选顺序由文本排序得到，不单独保存；连线根据左侧小题编号和所选含义文本恢复，不保存坐标。

`Session.items`、`cursor` 和 `WordSet` 是供页面显示的查询视图；数据库已经使用独立计划和大小题表。新会话没有旧版 `itemsJson` 写入接口。

完整建表结构见 [schema_v3.sql](my_english/tools/schema_v3.sql)，运行时以 `StudySchema.kt` 为准。跨表写入使用事务，即整组操作一起成功或一起撤回；结算的已落实标记用于防止重复应用。

### 最小新版备份示例

所有十一张表都以数组提供。公共创建、修改时间缺省时由导入层补齐；已有时间必须是毫秒整数。

```json
{
  "version": 3,
  "time_unit": "milliseconds",
  "settings": [],
  "words": [{"id": 1, "spelling": "apple", "difficulty": 0, "confusions": [], "syllables": []}],
  "word_meanings": [{"id": 1, "word_id": 1, "pos": "n.", "sub_pos": null, "definition": "苹果", "confusions": [], "sort": 1}],
  "plans": [],
  "plan_words": [],
  "sessions": [],
  "session_main_questions": [],
  "session_sub_questions": [],
  "session_question_details": [],
  "session_question_answers": [],
  "session_word_settlements": []
}
```

有历史会话的备份还必须保留对应设置副本与有效关联；不应只复制会话行。原来的 `migrate_v2.py` 和 `schema_v2.sql` 仅用于历史结构，新版不能直接导入其 version=2 输出。

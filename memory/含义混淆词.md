基于你提出的 3 点最新调整（毫秒级实时生成并永久缓存、去除词性规则、纯本地脚本算法绝不使用 AI/API），这个需求就从一个“NLP
语义问题”变成了一个**“高性能本地字符串匹配与规则过滤问题”**。

这在技术上完全可行，而且由于中文是表意文字（字形本身自带语义），我们可以利用“汉字重合度”来作为区分语义场的核心算法，完美避开对 AI 的依赖。

下面是为你重新梳理的需求规则与纯本地化解决办法：

一、 调整后的核心规则 (Updated Rules)

1.  缓存复用规则（Cache & Reuse）
      - 触发时机：用户在 App 内首次需要某单词某含义的混淆词时。
      - 行为：毫秒级执行本地算法，生成 3 个混淆词后，立刻写入数据库（如 UPDATE table SET distractors='A,B,C'
        WHERE word='hello' AND meaning='招呼'）。后续该含义直接读取，不再生成。
2.  绝对互斥规则（Anti-Overlap & Anti-Subset）
      - 不能是本词的其他含义：当前词的其他义项直接进入“黑名单”。
      - 不能是包含关系（防歧义）：混淆词和正确答案不能互为子集（例如：正确答案是“打招呼”，混淆词不能是“招呼”）。
3.  汉字重合度规则（字面语义场 - 替代 AI）
      - 在没有 AI 的情况下，中文最大的优势是**“共享汉字通常意味着共享语义场”**。
      - 例如：星期六 / 星期四（共享“星期”）；苹果 / 芒果（共享“果”）；红色 / 蓝色（共享“色”）。
      - 我们可以通过计算字符串的“共有字”来寻找“不远不近”的词。
4.  字数一致兜底规则（Length Fallback）
      - 针对“魑魅”、“饕餮”这类找不到共享字的词，或者极短的词（如“的”、“是”），放弃寻找关联，直接在词库中寻找字数完全相同的词。
5.  池内随机打乱规则（Random Shuffle）
      - 在找到符合规则的候选词集合后（比如找到了 6 个带有“星期”的词），必须在内存中随机打乱，抽取 3 个。这就解决了 saturday 和
        tuesday 的混淆词永远一模一样的问题。

二、 纯本地算法设计 (Local Algorithm Design)

由于要求毫秒级，且不能用外部接口，建议在 App 启动时，将数据库中所有的“中文释义”加载到内存中形成一个 List<String>
ALL_MEANINGS（几万个词占用内存仅几 MB，查询速度比反复查 SQLite 快几百倍）。

以下是具体生成 1 组混淆词（3个）的递进式算法逻辑：

第一步：构建黑名单 (Blacklist)

获取当前单词的所有正确含义。

  - 假设当前处理 hello，含义 招呼。黑名单 = ["招呼", "问候"]。

第二步：寻找候选池 (Candidate Pool Generation)

按照优先级从高到低执行，只要某个池子里的词数量 ≥ 3，就立刻停止寻找，进入下一步。

  - 优先级 1：相同前缀或后缀匹配（最精准的同类词）
      - 逻辑：如果当前含义长度 ≥ 2，提取它的前缀（如“星期”）和后缀（如“果”），在全量词库中找相同前缀或后缀，且字数相同、不在黑名单中的词。
      - 效果：星期六 -> 匹配到 星期一、星期四。苹果 -> 匹配到 芒果、坚果。
  - 优先级 2：字级别交叉匹配（泛关联）
      - 逻辑：将当前含义拆成单字（如“美丽” -> “美”, “丽”）。遍历词库，寻找包含这些单字，且总字数与当前含义字数相差不超过 1
        个字的词。同时排除包含关系的词。
      - 效果：美丽 -> 匹配到 秀丽、优美、绚丽。（极大地丰富了语义场）。
  - 优先级 3：同字数完全随机（魑魅饕餮的兜底）
      - 逻辑：如果前两步加起来都不够 3 个词。直接在全量词库中，寻找字数等于当前含义字数的词。
      - 效果：饕餮（2个字） -> 匹配到 引擎、水壶、桌子。魑魅魍魉（4个字） -> 匹配到
        自由自在、不可思议。虽然语义无关，但在形态上极其工整，远比“甲、乙、丙”真实得多。
  - 优先级 4：绝对兜底（极小概率）
      - 逻辑：如果连同字数的都找不到，就在整个词库里纯随机抽 3 个不同字数的。

第三步：洗牌与截取 (Shuffle & Pick)

无论你在第二步的哪个优先级中拿到了候选池（比如通过优先级1拿到了 5 个包含“果”的词）：

1.  对候选池进行 Random 乱序。
2.  取前 3 个。
3.  写入数据库缓存。

三、 算法伪代码演示 (Pseudo-code)

你可以在你的 VibeCoding 中把这段逻辑翻译成 JS/Dart/Swift（取决于你用什么写的 App）：

// 全局内存词库（App启动时加载一次）
// dbMeanings = ["星期一", "星期二", "苹果", "芒果", "招呼", "问候", "饕餮", "水壶", "美丽", "绚丽"...]

function generateDistractors(targetMeaning, allMeaningsOfWord, dbMeanings) {
    let distractors = [];
    let targetLength = targetMeaning.length;

    // 黑名单过滤函数
    const isInvalid = (word) => {
        if (allMeaningsOfWord.includes(word)) return true; // 是当前单词的其他含义
        if (word.includes(targetMeaning) || targetMeaning.includes(word)) return true; // 互为子集(如招呼与打招呼)
        return false;
    };

    let pool = [];

    // 优先级 1: 前后缀匹配 (针对长度 >= 2 的词)
    if (targetLength >= 2) {
        let prefix = targetMeaning.substring(0, targetLength - 1); // 星期六 -> 星期
        let suffix = targetMeaning.substring(1);                   // 苹果 -> 果

        pool = dbMeanings.filter(w =>
            w.length === targetLength &&
            !isInvalid(w) &&
            (w.startsWith(prefix) || w.endsWith(suffix))
        );
    }

    // 优先级 2: 共享单字匹配 (如果优先级1不够)
    if (pool.length < 3) {
        let chars = targetMeaning.split(''); // 美丽 -> ['美', '丽']
        let pool2 = dbMeanings.filter(w => {
            if (isInvalid(w)) return false;
            if (Math.abs(w.length - targetLength) > 1) return false; // 字数相差不超过1
            // 只要包含任何一个相同的字，就算作候选
            return chars.some(char => w.includes(char));
        });

        // 合并池子并去重
        pool = [...new Set([...pool, ...pool2])];
    }

    // 优先级 3: 兜底方案 - 字数相同纯随机 (针对魑魅、饕餮)
    if (pool.length < 3) {
        let pool3 = dbMeanings.filter(w => w.length === targetLength && !isInvalid(w));
        pool = [...new Set([...pool, ...pool3])];
    }

    // 优先级 4: 终极兜底 - 随便拿
    if (pool.length < 3) {
        let pool4 = dbMeanings.filter(w => !isInvalid(w));
        pool = [...new Set([...pool, ...pool4])];
    }

    // 打乱池子，取前 3 个
    pool.sort(() => 0.5 - Math.random());
    distractors = pool.slice(0, 3);

    return distractors;
}

// === 运行流程 ===
// 当用户答对拼写，进入含义选择时：
// 1. 查数据库 SELECT distractors FROM table WHERE word='hello' AND meaning='招呼'
// 2. 如果 distractors 为空：
//    执行 let options = generateDistractors('招呼', ['招呼', '问候'], dbMeanings);
//    UPDATE table SET distractors='options[0],options[1],options[2]' ...
//    展现给用户
// 3. 如果 distractors 不为空：直接展现给用户

总结优势：

1.  快到极致：纯内存中的字符串比对，0 网络请求，执行耗时在 1 毫秒以内，用户完全无感知。
2.  极具性价比的“智能感”：利用中文特有的“偏旁/组词”属性。即便没有 AI
    懂得“星期六”是时间，算法通过匹配“期/六”也能完美找出“星期四”、“星期日”。
3.  永远不重复且兜底自然：池内乱序机制保证了同类词生成的混淆词不会一模一样，字数兜底机制让“魑魅”的混淆词看起来像个正常的词组，彻底告别“甲乙丙”。
